# MCP-развязка медиа-генераций (музыка / картинки / видео)

status: идея, не начато
дата записи: 2026-11-05

## Суть

Медиа-генерация уезжает из Telegram-бота в **отдельный MCP-сервер `media`**, а интерфейсом
становится чат (Open WebUI, при желании — Hermes). Схема целевого вида:

```
WebUI (или Hermes) -> модель решила «сделай песню/картинку/видео»
                   -> tool call (MCP, streamable-HTTP, 127.0.0.1)
                   -> media-сервер: поставил задачу, сразу ответил «в работе»
                   -> генерация (музыка/картинка/видео)
                   -> mp3/png/mp4 на диск
                   -> доставка: файл в чат + Telegram sendAudio/sendPhoto/sendVideo
```

Тулы предполагаются узкие, без generic-обёрток:

- `request_song(prompt)` — песня по описанию (enricher-качество переезжает внутрь);
- `make_image(prompt)` — картинка;
- `make_video(prompt)` — видео (провайдера ещё нет, см. «Открытые вопросы»);
- `send_to_tg(artifact_id, chat)` — доставка готового артефакта в Telegram.

## Зачем

- **Один контейнер вместо пяти.** Сейчас `lyria-bot` + `lyria-generation-worker` +
  `lyria-enricher-worker` + `lyria-postgres` + `lyria-redis` + `lyria-rabbitmq`; у собственной
  Postgres бота нет бэкапов. Цепочка «сгенерировал → доставил» этого не требует.
- **Один набор тулов на всех клиентов.** MCP отдают тулы и в WebUI (семья пишет в чат), и в Hermes —
  вторую реализацию писать не надо. Поэтому MCP, а не OWUI-Function.
- **Интерфейс = чат.** Кнопки, меню и FSM в Telegram больше не нужны; семья формулирует запрос
  словами, а не помнит команды бота.
- **Доставка в TG по факту.** Результат приходит в мессенджер, когда готов, даже если вкладку
  WebUI давно закрыли.

## Что уже есть (проверено на хосте)

- `lyria-bot` работает через **OpenRouter напрямую**: `MODEL_ID=google/lyria-3-pro-preview`,
  `OPENROUTER_API_KEY` в его env. Свой маршрут, мимо LiteLLM.
- В `litellm_db` **уже заведена** модель `google/lyria-3-pro-preview` с `modalities:["audio"]`,
  `audio.format=mp3`, `stream:true` (создана 18.10.2026). Вызовов — 0, маршрут не обкатан.
- Картинки: `image_generation.engine=openai` -> `litellm:4000/v1` -> `img.openrouter/hy-image-v3.5-preview`;
  флаг `image_generation.enable` сейчас `false`, при этом сам эндпоинт отвечает.
- Видео: в LiteLLM **нет ни одного** video-маршрута (`veo|kling|sora|runway` — пусто).
- OWUI-вебхук как канал доставки медиа **не годится**: `utils/notifications.py` отправляет только
  события `chat finished / chat failed` с title и текстом, файлов там нет.

## Очередь и воркер — решение отложено

Требование владельца: **воркер нужен точно**, очередь обсуждается. Формулировка про «артефакт живёт
независимо от клиента» верна, но её обеспечивает порядок «сгенерил → записал на диск → отправил →
пометил доставленным» с идемпотентностью, а не брокер. Очередь даёт развязку по времени:
tool-call в OWUI умирает раньше, чем закончится генерация.

Варианты, которые надо взвесить (обсуждение — с тяжёлой моделью, отдельной итерацией):

1. **Postgres `FOR UPDATE SKIP LOCKED`** — ноль новых контейнеров, durability как у БД (с бэкапами),
   ретраи и heartbeat руками.
2. **faststream + Redis Streams** — ack/pending/ретраи из коробки, Redis уже есть; обязателен **AOF**,
   иначе стрим умирает вместе с процессом.
3. **faststream + RabbitMQ** — оправдано при нескольких потребителях на разных рантаймах; сейчас
   потребитель один.

Ограничение по OPINION владельца: `aiopika + taskiq` — не рассматривать.

## Открытые вопросы

- **Провайдер видео.** Пока нет ни маршрута, ни тула; MCP — только обёртка. Нужен провайдер
  (Veo / Kling / Sora через доступного брокера), цена за ролик и лимиты.
- **50 МБ Telegram Bot API** на отправку файла ботом: длинное видео не пролезет — либо локальный
  Bot API server, либо ссылка вместо файла.
- **Идти ли через LiteLLM** (`/v1/chat/completions`, модель `google/lyria-3-pro-preview`) или
  повторять путь бота напрямую в OpenRouter. Через шлюз — учёт расходов в `LiteLLM_SpendLogs`;
  напрямую — как сейчас у бота, но музыки не видно в спенд-логах.
- **Судьба enricher.** Стихи → критик → санитайзер → JSON — единственная часть бота, которую стоит
  перенести как есть; вопрос, тащить ли её в тул целиком или упростить до одного промпта.
- **Что делать со старой обвязкой** (6 контейнеров + собственная БД без бэкапов): выключать после
  пилота или оставить как фолбэк на время проверки.
- **Права семьи.** Кто из юзеров WebUI получает тулы, и что мешает им генерить видео пачками.
