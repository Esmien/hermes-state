# VPN-стек: как устроен и как собрать с нуля

Документ для того, кто хочет понять систему целиком и повторить её руками.
Всё описано по состоянию на 7 ноября 2026, проверено командами на живом сервере.
Секретов здесь нет: токены, UUID и ключи лежат в файлах, пути указаны, значения — нет.

---

## 1. Коротко

Один входной сервер (Эстония) принимает клиентов по VLESS+WebSocket+TLS на порту 8443.
Дальше решение принимает **сервер**, а не клиент: трафик к Google уходит через Францию
(резерв — Финляндия), трафик к российским сайтам — через отдельный бокс в Москве,
всё остальное выходит напрямую с эстонского сервера.

Клиент видит в приложении **одну строку**. Никаких «выбери страну» — выбирать нечего.

Что стоит сейчас: 6 человек, 12 подписок (основная и белые списки на каждого),
24 входящих пути (инбаунда), 25 исходящих (аутбаунда), 29 правил маршрутизации.

---

## 2. Схема

```
Happ / mihomo на телефоне или ноутбуке
        │  TLS, порт 8443 (резерв 2087), сертификат *.esmien.ru
        ▼
   nginx  ── терминирует TLS, раздаёт подписки, проксирует WS по пути
        │  http://127.0.0.1:1008x (только loopback)
        ▼
   xray (контейнер vpn-router, --network host)
        │  определяет, куда идёт запрос:
        │
        ├─ google.com / googleapis / gstatic / google.dev …  → bal-google → Франция
        │                                                      (Финляндия как резерв)
        ├─ домены .ru / .su / .рф                            → bal-ru → свой бокс в Москве
        │                                                      (фоллбэк — Эстония)
        └─ всё остальное                                     → direct, выход Эстонии
```

Второй контейнер (`vpn-router-b`) держит ту же конфигурацию на портах +1000.
Трафик переключается между ними при применении конфига — это blue-green,
чтобы правка не роняла соединения.

## 3. Почему именно так: решения и их цена

| Решение | Зачем | Чем платим |
|---|---|---|
| VLESS+WS+TLS на **8443**, а не на 443 | Домашний провайдер режет 443 и fake-TLS, но пропускает настоящий TLS на нестандартном порту | Клиент должен знать нестандартный порт; адрес подписки выглядит необычно |
| TLS терминирует **nginx**, xray слушает только loopback | Сертификаты, подписки и страницы в одном месте; xray не трогает привилегированные порты | Лишний слой: сломался nginx — сломался вход |
| **24 отдельных инбаунда** (по одному на путь) | Каждый путь жёстко привязан к своему выходу; так одно правило не влияет на другие | Конфиг 51 КБ; править руками нельзя, только генератором |
| Маршруты решает **сервер**, а не клиент | Клиент не может случайно увести трафик не туда и не жжёт чужую подписку | Нет ручного выбора страны; новый сценарий = правка на сервере |
| В подписке **один узел** | Лишние модели = лишний трафик через чужие релеи = выше шанс бана | Нельзя «попробовать другой сервер» из приложения |
| Белые списки — **отдельная подписка** и напрямую | Первый хоп через наш зарубежный IP отваливается первым при блокировках | На человека две подписки вместо одной |
| **Сторож** раз в минуту с джиттером | Умерший релей выбивается из балансера сам, без человека | До минуты, пока сценарий переключится |
| Свой **РФ-бокс** вместо чужих релеев | Госуслуги и банки перестали зависеть от чужой подписки за 160 ₽ | Ещё одна машина, которую надо обновлять |

## 4. Компоненты: что где лежит

| Что | Где |
|---|---|
| Конфигурация xray | `/root/vpn-router/config.json` (рабочая), `config.b.json` (второй цвет) |
| Генератор сценариев | `/root/vpn-router/scenario_routes.py` — балансеры, observatory, правила |
| Сторож | `/root/vpn-router/scenario_fallback.py`, лог `/var/log/scenario-fallback.log` |
| Применение конфига | `/usr/local/bin/vpn-cfg` (`status` / `edit` / `apply` / `rollback`) |
| Blue-green | `/root/vpn-router/vpn-bluegreen.py`, активный цвет в `/root/vpn-router/vpn-color` |
| Генератор подписок | `/root/vpn-router/make_sub.py` (режимы: обычная, `meta`, `whitelist`) |
| Страницы подписки | `/root/vpn-router/make_pages.py` → `/var/www/esmien-pages/<токен>.html` |
| Файлы подписок | `/var/www/esmien-sub/<токен>/{list.txt,clash.yaml,singbox.json,announce,kind}` |
| Пользователи | `/root/vpn-router/users.json` (имя, токен, второй токен для белых списков) |

| Таймеры | `vpn-scenarios.timer` (сторож), `vpn-sub-expiry.timer` (сроки подписок) |

| Клиент (ноутбук) | `/opt/mihomo/mihomo`, `/etc/mihomo/config.yaml`, `/usr/local/bin/vpn`, `mihomo.service` |

## 5. Что происходит с одним запросом

1. Клиент устанавливает TLS к `vpn.esmien.ru:8443` и открывает WebSocket по своему пути
   (`/general` — основной; `/france`, `/fi`, `/test`, `/p<i>` — служебные).
2. nginx снимает TLS и проксирует WS на соответствующий loopback-порт (`/general` → 10082).
3. xray принимает соединение в инбаунде с тегом `in-general`, смотрит на домен
   из SNI (имя сайта в TLS-рукопожатии) и на адрес назначения.
4. Домен попадает под одно из правил: Google → балансер `bal-google`, `.ru` → `bal-ru`,
   остальное → `direct`.
5. Балансер берёт лучший по задержке живой узел (стратегия `leastPing`),
   данные о задержках обновляет `observatory` раз в 30 секунд.
6. Запрос уходит в выбранный аутбаунд: `fr` (Франция), `fi`, `ru1` (свой бокс), `direct` (Эстония).
7. Если все узлы группы мертвы, сторож переводит группу на `direct` — то есть на Эстонию.

**Важно:** содержимое трафика не вскрывается. Решение принимается по имени домена
из TLS-рукопожатия и по IP-подсетям Google. Расшифровки и DPI на сервере нет.

## 6. Где кончается «просто» и начинаются ограничения

- **QUIC не виден.** HTTP/3 идёт по UDP, где имени домена нет. Если клиент не блокирует
  QUIC, часть запросов Google уедет мимо сценария. Лечится отключением QUIC на клиенте
  либо правилом, которое режет UDP/443.
- **Только TCP-сайты в правилах по домену.** Всё, что ходит по голому IP без SNI,
  попадает под правило по IP-подсети или уходит в `direct`.
- **Сертификат на домен, а не на IP.** Значит нужен DNS; если DNS домена ляжет,
  клиенту некуда подключаться. От этого спасают дубли узлов «по IP» в старых подписках.

## 7. Сборка с нуля

### Шаг 0. Что нужно принести самому

- VPS с Ubuntu 24.04 (для этого стека хватает 1 vCPU / 2 ГБ / 20 ГБ).
- Домен и доступ к его DNS (сертификат выпускается через DNS-01, порт 80 не нужен).
- **Чужие релеи**, если нужны сценарии Gemini и РФ. Без них остаётся один выход —
  ваш собственный сервер, и вся география исчезает. Это главное ограничение схемы.

### Шаг 1. Система

```bash
apt update && apt -y upgrade
apt -y install curl jq python3 nginx certbot docker.io
systemctl enable --now docker nginx
```

Проверка: `docker version`, `nginx -v`, `python3 -V`.

### Шаг 2. DNS и сертификат

A-запись домена → IP сервера. Сертификат на wildcard выпускается через DNS-01
(у Cloudflare — плагин `python3-certbot-dns-cloudflare`), затем:

```bash
certbot certonly --dns-cloudflare -d '*.example.com' -d example.com
certbot renew --dry-run
```

Проверка: `certbot certificates` показывает срок; `--dry-run` проходит без ошибок.
Продление должно быть автоматическим, иначе вход умрёт через 90 дней.

### Шаг 3. Конфигурация xray

Конфиг **генерируется**, руками не правится. Минимум, что должно быть:

- инбаунды: по одному VLESS+WS на каждый путь, слушают `127.0.0.1`;
- аутбаунды: `direct`, релеи (trojan или vless), свой РФ-бокс;
- `routing.rules`: private и bittorrent в блок, домены Google → `bal-google`,
  домены `.ru` → `bal-ru`, дальше правила по инбаундам, в конце catch-all → `direct`;
- `routing.balancers`: группы со стратегией `leastPing`;
- `observatory`: список узлов, `probeUrl`, интервал 30 секунд.

Проверка конфига до запуска:

```bash
docker run --rm --user 0:0 --entrypoint /usr/local/bin/xray \
  -v /root/vpn-router/config.json:/etc/xray/config.json:ro \
  ghcr.io/xtls/xray-core:latest run -test -c /etc/xray/config.json
```

### Шаг 4. Nginx

Два server-блока: 8443 (основной) и 2087 (резерв). В каждом:

- `location /general` и остальные пути → `proxy_pass http://127.0.0.1:1008x`
  с `Upgrade`/`Connection` для WebSocket;
- `location ~ ^/sub/<токен>$` → отдача файла подписки, имя файла выбирается по User-Agent
  (Clash/Happ/sing-box получают разный формат — карта в `00-esmien-sub-map.conf`);
- `location ~ ^/u/<токен>$` → HTML-страница с описанием подписки.

Проверка: `nginx -t`, затем `curl -k https://домен:8443/sub/<токен> | head -c 100`.

### Шаг 5. Подписки

`users.json`: имя → токен (и второй токен для белых списков). Генератор создаёт на каждого:

- `list.txt` — base64-список VLESS-ссылок (Happ, большинство клиентов);
- `clash.yaml` — для Clash/mihomo/FlClash;
- `singbox.json` — для sing-box;
- `announce` — текст, который клиент показывает как описание подписки;
- `kind` — режим: пусто (обычная), `meta` (один узел, сценарии на сервере), `whitelist`.

Проверка: `curl -A 'ClashMeta/1.19.33' https://домен:8443/sub/<токен> | head -30`.

### Шаг 6. Сторож

Юнит `vpn-scenarios.service` + таймер раз в минуту со случайной задержкой до 30 секунд
и джиттером старта до 20 секунд (чтобы не бить по расписанию и не выглядеть ботом).

Логика: поднять временный клиент xray, прогнать по каждому узлу TCP-хендшейк
и HTTP-запрос через него, живые оставить в балансере, мёртвых выкинуть,
всё живое — вернуть. Узел вылетает только после **2 провалов подряд** (счётчики
в `scenario_state.json`), а не с одной икоты. Конфиг перечитывается перед записью
(иначе сторож затирает чужие правки).

**Сторож пишет только черновик.** Он больше не вызывает `vpn-cfg apply`: раньше он
держал `/var/lock/vpn-config.lock` и apply брал ту же блокировку — сторож ждал сам
себя 300 секунд и падал, то есть не применял ничего вообще. Живой фоллбэк теперь
делает сам xray через `fallbackTag` у балансировщика (`bal-google`→`fi`,
`bal-ru`→`direct`): узел замолчал — трафик ушёл на резерв за ~30–60 с, без правки
файлов и без рестарта контейнера.

Для РФ-узлов проверка идёт по российским адресам: `http://www.tbank.ru/`,
`http://www.avito.ru/` (по HTTP — у них российские корни сертификатов и тяжёлые
страницы по HTTPS), `https://www.gosuslugi.ru/`. Живым считается **любой** ответ
кроме `000`: 403/429 от банка или маркетплейса доказывают, что путь работает.

Раз в 10–15 минут (с джиттером) сторож проверяет страну Gemini у выходов Google:
тянет `gemini.google.com/app` и читает `cc` из `this.gbar_={CONFIG:…}` — Эстония
отдаёт `ru` (заблокировано), Франция `co.uk` (работает). Строки «недоступно в вашей
стране» в незалогиненной странице нет вообще, искать её бессмысленно.

Проверка: `tail -3 /var/log/scenario-fallback.log` — там строка вида
`fr:ok(61ms) fi:ok(43ms) ru1:ok(33ms) | bal-google=['fr'] bal-ru=['ru1'] | fails={}`.

### Шаг 7. Применение конфига (blue-green)

`vpn-cfg apply`:

1. пересобирает конфиг для неактивного цвета (порты +1000);
2. валидирует его тестовым запуском;
3. перезапускает неактивный контейнер;
4. проверяет, что все 24 инбаунда отвечают;
5. переключает nginx на новый цвет;
6. оставляет старый контейнер живым до следующего применения.

Проверка: `vpn-cfg status` — цвет, состояние контейнеров, число живых инбаундов.
Откат: `vpn-cfg rollback`.

### Шаг 8. Свой выход в РФ (если нужен)

Отдельная машина, xray с одним инбаундом VLESS+Reality на 443:

- Reality не требует сертификата и не отличается от обычного TLS-сайта для DPI;
- `dest` — реальный сайт с TLS 1.3 (например `www.microsoft.com:443`);
- фаервол: 443 только с IP входного сервера, 22 только по ключам;
- **обязательно** `domainStrategy: UseIPv4` на freedom-аутбаунде: у машины нет IPv6,
  и попытка идти по AAAA-записи вешает соединение намертво (проверено на Wildberries).

Проверка до включения в маршрут:

```bash
curl -sk -o /dev/null -w '%{http_code}\n' https://www.gosuslugi.ru   # ждём 200/307
curl -sk -o /dev/null -w '%{http_code}\n' https://www.sberbank.ru     # ждём 200
```

Если Госуслуги отдают `000` — адрес датацентровый и в чёрном списке, менять машину.

### Шаг 9. Клиент

Два равноправных варианта:

- **Приложение** (Happ, FlClash): вставить ссылку подписки, обновлять раз в 12 часов.
- **Демон без окон** (Linux): mihomo в режиме TUN как systemd-служба + скрипт
  `vpn on|off|status`. Профиль тянется с той же ссылки, TUN-интерфейс поднимается
  автоматически, `vpn off` освобождает машину для другого клиента.

Проверка: `curl -s https://ipinfo.io/ip` после включения должен вернуть IP выхода,
а не домашний.

## 8. Диагностика: шесть команд

```bash
# 1. Что вообще с сервисом и активным цветом
vpn-cfg status

# 2. Живы ли контейнеры
docker ps --filter name=vpn-router --format '{{.Names}} {{.Status}}'

# 3. Что решил сторож в последний прогон
tail -3 /var/log/scenario-fallback.log

# 4. Прошёл ли конкретный сценарий (с рабочей машины через туннель)
curl -s -o /dev/null -w 'gosuslugi %{http_code}\n' https://www.gosuslugi.ru
curl -s -o /dev/null -w 'gemini %{http_code}\n' https://gemini.google.com

# 5. Не сломали ли nginx
nginx -t && systemctl is-active nginx

# 6. Что видит сервер в логах xray (последние 20 строк)
journalctl -u vpn-scenarios -n 20 --no-pager
```

Типовые ответы:

| Симптом | Причина | Что смотреть |
|---|---|---|
| Госуслуги не открываются | Группа `bal-ru` ушла на `direct`, а из Эстонии они режут | п. 3, `bal-ru` в логе |
| Gemini отдаёт «недоступно в вашей стране» | `bal-google` указывает на неподходящий узел | п. 3, `bal-google` |
| Ничего не открывается | nginx или контейнер | п. 1, п. 2, п. 5 |
| Сайты открываются, но медленно | выбран далёкий релей | п. 3, задержки в скобках |
| Подписка пустая или старая | не пересобралась | `ls -l /var/www/esmien-sub/<токен>/` |

## 9. Грабли, на которые мы реально наступили

1. **FlClash держит те же ресурсы.** Пока он запущен, mihomo не поднимает TUN:
   `bind: address already in use` на 7890 и `add route 0: file exists`.
   Перед `vpn on` другой клиент надо закрывать.
2. **DNS домена может не отвечать.** Поэтому в старых подписках узлы дублировались
   «по IP» — это не косметика, а спасение в момент, когда резолвер молчит.
3. **Проверка живости через gstatic ломает РФ-узлы.** Из российского датацентра
   Google не отвечает — узел помечается мёртвым, и весь РФ-сценарий отваливается.
   Для РФ-узлов проверка идёт по российским адресам.
4. **Сторож должен принимать 3xx.** `ya.ru` отвечает `302`, и проверка «только 200/204»
   объявляла живой узел мёртвым.
5. **Потерянные обновления.** Сторож писал свою копию конфига и воскрешал удалённый
   балансер. Лечится блокировкой файла и перечитыванием конфига перед записью.
6. **cloud-init перебивает sshd.** `PasswordAuthentication no` в своём файле не работает,
   если `50-cloud-init.conf` говорит `yes`: в sshd выигрывает первое значение.
   Правится в обоих местах плюс `ssh_pwauth: false` в cloud.cfg.
7. **Happ обрезает описание подписки** примерно на трёх строках. Длинный текст
   бесполезен: нужен один абзац до ~170 символов, без base64.
8. **Кириллица в комментариях `clash.yaml`** превращается в кракозябры в FlClash.
   Шапка файла — только ASCII.
9. **Reality на машине без IPv6.** Если домен отдаёт AAAA-запись, а IPv6 нет,
   соединение висит до таймаута. Спасает `domainStrategy: UseIPv4`.

## 10. Границы: что эта схема не делает

- **Один вход.** Вторая машина не поднимается автоматически: упадёт вход — упадёт всё.
  Это осознанное решение по бюджету, время восстановления — до суток.
- **Чужие релеи однодевайсные.** Одна подписка = одна нода, 160 ₽ в месяц.
  Пять входов = пять подписок, если провайдер считает по устройствам.
- **Парк входов = строки в клиенте.** Если входов станет N, в приложении будет N строк;
  маршруты при этом всё равно решает сервер, но выбор входа остаётся человеку.
- **Нет лимитов на ключи и нет алертов.** Так задумано: контур частный, следит владелец.
- **Белые списки — серая схема.** Они живут на узлах провайдера и от него зависят;
  при его отказе или бане подписка перестаёт работать целиком.
- **QUIC вне правил.** Пока клиент не отключил HTTP/3, часть трафика идёт мимо сценария.

## 11. Если упаковывать это в продукт

Порядок, который не приведёт к «коду без объяснений»:

1. один файл правды (`stack.yaml`: домен, порты, пользователи, входы, выходы, сценарии);
2. генератор, который собирает из него `config.json`, подписки и nginx-конфиги;
3. CLI (`init`, `apply`, `user add`, `check`) и docker compose;
4. installer, который спрашивает домен, e-mail, релеи и создаёт первого пользователя.

Этот документ — техзадание на такую упаковку: всё, что здесь описано словами,
должно превратиться в один генератор и одну команду.
