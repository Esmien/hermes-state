# ТЗ: песочница на пользователя

Версия 2 (итоговая). Снимок данных: 2026-11-09, 20:10 UTC. Числа сняты с живой машины.

## 1. Задача

Сейчас терминал-песочница одна на всех: общий потолок 2 ГБ, общий рабочий каталог 6.7 ГБ, доступ выдан всем 11 пользователям (`principal_id "*"`). Два тяжёлых запроса одновременно — песочница отваливается у всех сразу, файлы видны всем.

Нужно: у каждого пользователя свой терминал со своим потолком и своим каталогом, без потери возможности ставить нужные пакеты.

## 2. Как устроено после внедрения

Три части.

**Ядро.** Текущий контейнер песочницы Игоря (со всеми ядрами Arduino, библиотеками, pip-пакетами) превращается в служебный контейнер с тулчейном. Грантов на него нет ни у кого, кроме администратора. Это единственное место, где руками ставится то, что нельзя поставить в пользовательский каталог. Игорь получает новый пустой контейнер и свой каталог; старые файлы (скетчи, сборки, черновики, `.tmp`) остаются лежать в томе ядра — не удаляем, не переносим, они мусор и наружу не видны.

**Пользовательские контейнеры.** 11 штук, по одному на пользователя с ролью «Пользователь». Тот же образ, та же прошивка: не-root `1000:1000`, `cap_drop: ALL`, `read_only` корень, без docker.sock, без монтирования хоста. Внутри — только свой каталог.

**Provisioner.** Скрипт на хосте + systemd-таймер раз в минуту. Смотрит пользователей в базе WebUI и приводит контейнеры и соединения к нужному состоянию. Он же считает размер каталогов и чистит по LRU.

## 3. Что видит пользователь

В файловом браузере — одна папка: своя рабочая (по имени пользователя). Больше ничего.

Ядро в домашний каталог не монтируется: оно висит в `/opt/toolchain` только на чтение и прописано в `PATH` и `PYTHONPATH`. Инструменты работают, потроха не на витрине. `ls /` их покажет — это не секрет, просто не выставляется в интерфейсе.

## 4. Лимиты и правила

| Параметр | Значение | Зачем |
|---|---|---|
| Память | 1.5 ГБ на контейнер | 2 ГБ × 11 физически не влезают в 8 ГБ |
| Своп | `memswap_limit 2g` = 1.5 памяти + 0.5 свопа | сейчас у контейнеров `memswap_limit == mem_limit`, то есть своп запрещён; без этой правки сценарий «пережить пик на четырёх в свопе» не работает |
| CPU | 1 ядро на контейнер | доли, не резервация: 11 долей на 4 ядра, при конкуренции делятся поровну |
| Процессы | 256 | как сейчас |
| Диск на пользователя | 2 ГБ, LRU | чистим самое старое по mtime (atime врёт из-за relatime) |
| Неприкосновенные каталоги | `~/.local`, `~/venv`, `~/bin` | установленные пакеты не эвиктятся; если сами перевалили 2 ГБ — алерт владельцу, решает он |
| Файлы удалённого пользователя | 3 дня | потом каталог удаляется |
| Роль «Ожидает» | контейнер не создаётся | только после приёмки до роли «Пользователь» |
| Роль «Админ» | контейнер не создаётся, грант снимается | админ ходит в ядро и в свой каталог как владелец |

Проверено на живой машине: своп 4 ГБ, из них 1.1 ГБ занят хостом, свободно ~3 ГБ, `swappiness 10`. Четверо по 1.5 ГБ = 6 ГБ против 4.1 ГБ свободной памяти → ~1.9 ГБ уходит в своп, влезает. При выходе за 2 ГБ cgroup убивает **свой** контейнер, WebUI остаётся жив.

## 5. Установка пакетов

**Уровень 1 — пользователь сам, привилегий не нужно.** Проверено в контейнере с теми же ограничениями (не-root, `cap_drop: ALL`, корень только на чтение):
- `pip3 install --user` — встал `requests 2.34.2`, импортируется;
- `npm install --prefix ~/.local`, `venv`, статические бинари в `~/bin` — тот же механизм;
- системный `.deb` без root: скачать с `deb.debian.org`, распаковать `dpkg-deb -x` в свой каталог, запустить (проверено: `hello` → `Hello, world!`);
- `apt` не работает — нет root и корень только на чтение.

**Уровень 3 — руками в ядре.** Всё, что требует системы: демоны, глобальные пути, модули. Заходишь в контейнер ядра, ставишь, мгновенно видят все. Перед изменениями — tar-бэкап каталогов ядра.

**Как модели узнают рецепты — не через системные промпты моделей.** У Open Terminal есть собственный системный промпт: переменная `OPEN_TERMINAL_SYSTEM_PROMPT`, отдаётся по `GET /system`. Проверил в коде Open WebUI: `utils/tools.py` забирает этот промпт, `utils/middleware.py` подставляет его в контекст — то есть он приезжает в **любой** чат, где выбран этот терминал, без правки моделей. Рецепты пишутся один раз — в шаблоне контейнера.

Дополнительно: `AGENTS.md` только на чтение в `/opt/toolchain/` — для случая, когда внутри терминала запускают кодового агента (Codex, Claude Code), который такие файлы читает сам. Необязательная часть, основной канал — системный промпт терминала.

## 6. Ядро и Arduino

Ядра Arduino и библиотеки остаются в томе ядра (`/workspace/.arduino15` 6.3 ГБ, `Arduino/` 49 МБ, `.local` 23 МБ).

- Монтирование пользователям — **не** всего `/workspace` (иначе весь мусор станет виден), а точечно: `.arduino15`, `Arduino`, `.local` (bind-mount подкаталогов хоста, только чтение).
- Arduino — **только Игорю**, остальные 10 контейнеров без ядер вообще.
- Игорю данные Arduino нужны записываемыми (туда пишутся staging и новые ядра), поэтому ядра не монтируются, а раскидываются жёсткими ссылками в его каталог: файлы на диске общие, каталог его. Если он поставит новую версию ядра — разойдётся с ядром, это его локальная копия, так и задумано.

## 7. Из чего состоит

| Файл / юнит | Что делает |
|---|---|
| `/home/ai_service/sandbox-users/template.compose.yml` | шаблон пользовательского контейнера: `SB_SLUG`, `SB_KEY`, пути, лимиты |
| `/home/ai_service/sandbox-users/state.json` (0600) | карта «пользователь → слаг, контейнер, ключ, лимиты, дата создания» |
| `/usr/local/bin/sandbox-provisioner.py` | сверка состояния, docker compose, соединения через админ-API WebUI, LRU-чистка |
| `sandbox-provisioner.service` + `.timer` | запуск раз в минуту, лог в журнал |
| `/home/ai_service/sandbox/users/<слаг>/` | рабочий каталог пользователя на хосте (uid 1000) |
| `/home/ai_service/sandbox/core/` | симлинки на каталоги ядра для монтирования (одно место, если ядро переедет) |

Ключи: свой на каждый контейнер, только в `state.json` и в окружении контейнера. В git не попадают, в чат не печатаются.

## 8. Жизненный цикл

**Пользователь принят** (роль «Пользователь»): provisioner создаёт каталоги, генерирует ключ, поднимает контейнер, ждёт `healthy`, и только после этого добавляет соединение в WebUI с грантом на этого пользователя. Первые 30–60 секунд после приёмки терминал ещё не виден — лучше, чем соединение с ошибкой.

**Смена роли на «Ожидает» или «Админ»:** грант снимается, контейнер стопается.

**Пользователь удалён:** снимается соединение, контейнер гасится, каталог живёт 3 дня, потом удаляется.

**Ребут хоста:** контейнеры поднимаются сами (`restart: always`), таймер сверяет состояние и чинит расхождения (контейнер без соединения — добавит; соединение без пользователя — уберёт).

**Изменить лимит:** правится одна запись в `state.json`, таймер пересоздаёт контейнер с новыми лимитами.

## 10. Трейдоффы

| Решение | Зачем | Чем платим |
|---|---|---|
| Контейнер на пользователя | отказ одного не трогает остальных | 11 контейнеров, ~340 МиБ в простое, 11 записей в админке |
| Ядро как общая точка | не пересобирать тулчейн на каждого, мгновенные обновления | битый пакет в ядре ломает всех; правки только руками админа + бэкап перед ними |
| 1.5 ГБ + 0.5 свопа | пережить пик четырёх | тяжёлые сборки (esp32, крупные скетчи) могут не влезть — поднимаем точечно |
| 1 CPU на контейнер | пользователи редкие, душить заранее глупо | при одновременной компиляции все ждут |
| LRU 2 ГБ | диск не бесконечен | старые рабочие файлы исчезают; установленные пакеты защищены отдельно |
| Рецепты в промпт терминала | не править модели руками | промпт приезжает ко всем, кто в этом терминале; нужно разное поведение — заводим второй терминал |
| Проверка раз в минуту | не нужен вебхук, работает после ребута | до минуты задержка на создание и удаление |

## 11. Что это не решает

- **Физический предел машины.** Четверо по 1.5 ГБ плюс стек — своп на пределе. Контейнеры разводят отказы, но памяти не добавляют.
- **Диск общий.** 2 ГБ на пользователя считает наш скрипт, а не файловая система: если скрипт упал, никто не мешает залить весь диск. Настоящая квота — только на уровне ФС.
- **Сеть стека.** Из песочницы видно `litellm`, `postgres`, `open-webui` — без учётных данных доступа нет, но это не изоляция. Строже — отдельная сеть, к которой подключён только WebUI.
- **Мусор в ядре.** 6.7 ГБ старых файлов Игоря остаются на диске.
- **Общее ядро.** Настоящая изоляция требует отдельной машины.

## 12. Этапы

**Фаза 1 — шаблон и ручной прогон.** Шаблон compose, один контейнер вручную, проверка прошивки (uid 1000, нет docker.sock, `/etc` только на чтение, `cap_drop` применён), системный промпт с рецептами. Соединение создаём через админ-API.
*Проверка:* тестовый пользователь просит `id` и `ls` — видит свой uid и свою папку; `pip install --user` работает; чужого контейнера в списке нет.

**Фаза 2 — provisioner и LRU.** Скрипт, таймер, состояние, чистка по размеру.
*Проверка:* создать пользователя → появились контейнер и соединение; удалить → соединение убрано, контейнер погашен, каталог на месте; два прогона подряд дублей не дают; раздутый каталог чистится до 2 ГБ, `.local` не тронут.

**Фаза 3 — раскатка.** 11 контейнеров, ядро без грантов, Игорь получает чистый контейнер с ядрами ссылками, общая песочница перестаёт быть общей.
*Проверка:* `docker ps` — 11 контейнеров; у каждого ровно один терминал в чате; доступ к ядру только у администратора.

**Фаза 4 — порядок.** Шаблон, скрипт, юниты в git; скилл обновлён; мусор после себя убран.

**Откат:** снять соединения пользователей, вернуть грант на общую песочницу всем — 10 минут, данные не теряются.

## 13. Зафиксированные решения

1. Файлы удалённого пользователя — 3 дня.
2. Лимиты — 1.5 ГБ памяти / 1 CPU, своп 0.5 ГБ.
3. Потолок каталога — 2 ГБ, LRU.
4. Ядра Arduino — только Игорю.
5. «Ожидает» — контейнер не создаётся.
6. Игорь — чистый лист, старые файлы не переносим и не архивируем.
7. Пакеты — уровни 1 (userspace) и 3 (руками в ядре); очередь заявок не строим.
8. Рецепты для моделей — системный промпт терминала, не системные промпты моделей.
9. `system` пользователю не показываем: `/opt/toolchain`, только чтение, в `PATH`.
10. Multi-user mode самого Open Terminal отклонён: требует root внутри контейнера.

## 14. Оценка

3–4 часа по фазам. Больше всего времени — фаза 1 (проверка, что прошивка и промпт не поехали) и отладка админ-API при создании соединений.
