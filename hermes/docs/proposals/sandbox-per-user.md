# ТЗ: песочница на пользователя

Версия 3 (итоговая). Снимок данных: 2026-11-09, 20:55 UTC. Числа сняты с живой машины.

Изменение против версии 2: **общего ядра с пакетами нет**. Всё, что нужно под задачу, пользователь ставит себе сам; общий слой — только образ. Тулчейн Arduino из старой песочницы удалён, Игорь сейчас ничем не отличается от остальных.

## 1. Задача

Сейчас терминал-песочница одна на всех: общий потолок 2 ГБ, общий рабочий каталог, доступ выдан всем 11 пользователям (`principal_id "*"`). Два тяжёлых запроса одновременно — песочница отваливается у всех сразу, файлы видны всем.

Нужно: у каждого пользователя свой терминал со своим потолком и своим каталогом, без потери возможности ставить нужные пакеты.

## 2. Как устроено после внедрения

Две части.

**Пользовательские контейнеры.** 11 штук, по одному на пользователя с ролью «Пользователь». Тот же образ, та же прошивка: не-root `1000:1000`, `cap_drop: ALL`, `read_only` корень, без docker.sock, без монтирования хоста. Внутри — только свой рабочий каталог.

**Provisioner.** Скрипт на хосте + systemd-таймер раз в минуту. Смотрит пользователей в базе WebUI и приводит контейнеры и соединения к нужному состоянию. Он же считает размер каталогов и чистит по LRU.

Общего тома с пакетами нет. Общий слой — образ `esmien/open-terminal-arduino:local`: если пакет нужен **всем**, он ставится в образ и контейнеры пересоздаются (данные в каталогах при этом не теряются).

## 3. Что видит пользователь

В файловом браузере — одна папка: своя рабочая. Больше ничего: ни служебных каталогов, ни чужих файлов, ни общей свалки.

## 4. Лимиты и правила

| Параметр | Значение | Зачем |
|---|---|---|
| Память | 1.5 ГБ на контейнер | 2 ГБ × 11 физически не влезают в 8 ГБ |
| Своп | `memswap_limit 2g` = 1.5 памяти + 0.5 свопа | сейчас у контейнеров `memswap_limit == mem_limit`, то есть своп запрещён; без этой правки «пережить пик на четырёх в свопе» не работает |
| CPU | 1 ядро на контейнер | доли, не резервация: 11 долей на 4 ядра, при конкуренции делятся поровну |
| Процессы | 256 | как сейчас |
| Диск на пользователя | 2 ГБ, LRU | чистим самое старое по mtime (atime врёт из-за relatime) |
| Неприкосновенные каталоги | `~/.local`, `~/bin`, `~/venv`, `~/.arduino15`, `~/Arduino` | пакеты и тулчейны не удаляются; если сами перевалили 2 ГБ — алерт владельцу |
| Файлы удалённого пользователя | 3 дня | потом каталог удаляется |
| Роль «Ожидает» | контейнер не создаётся | только после приёмки до роли «Пользователь» |
| Роль «Админ» | контейнер не создаётся, грант снимается | админ при необходимости ходит вручную |

Проверено на живой машине: своп 4 ГБ, из них 1.1 ГБ занят хостом, свободно ~3 ГБ, `swappiness 10`. Четверо по 1.5 ГБ = 6 ГБ против 4.1 ГБ свободной памяти → ~1.9 ГБ в своп, влезает. При выходе за 2 ГБ cgroup убивает **свой** контейнер, WebUI остаётся жив.

## 5. Установка пакетов

**Пользователь сам, привилегий не нужно.** Проверено в контейнере с теми же ограничениями (не-root, `cap_drop: ALL`, корень только на чтение):
- `pip3 install --user` — встал `requests 2.34.2`, импортируется;
- `npm install --prefix ~/.local`, `venv`, статические бинари в `~/bin` — тот же механизм;
- системный `.deb` без root: скачать с `deb.debian.org`, распаковать `dpkg-deb -x` в свой каталог, запустить (проверено: `hello` → `Hello, world!`);
- `arduino-cli core install` / `lib install` — пишут в `~/.arduino15` и `~/Arduino` внутри рабочего каталога;
- `apt` не работает — нет root и корень только на чтение.

**Нужно всем — в образ.** Пересборка `esmien/open-terminal-arduino:local` и пересоздание контейнеров: 3–5 с на контейнер, каталоги сохраняются. Это же путь для «системных» пакетов, которым при установке нужен root: внутрь контейнера root не даётся никогда.

**Как модели узнают рецепты.** У Open Terminal есть собственный системный промпт: `OPEN_TERMINAL_SYSTEM_PROMPT`, отдаётся по `GET /system`. В Open WebUI `utils/tools.py` его забирает, `utils/middleware.py` подставляет в контекст — приезжает в **любой** чат с этим терминалом, править модели не нужно. Текст лежит в шаблоне контейнера.

## 8. Жизненный цикл

**Пользователь принят** (роль «Пользователь»): provisioner создаёт каталог, генерирует ключ, поднимает контейнер, ждёт `healthy`, и только после этого добавляет соединение в WebUI с грантом на этого пользователя. Первые 30–60 секунд после приёмки терминал не виден — лучше, чем соединение с ошибкой.

**Смена роли на «Ожидает» или «Админ»:** грант снимается, контейнер стопается.

**Пользователь удалён:** снимается соединение, контейнер гасится, каталог живёт 3 дня, потом удаляется.

**Ребут хоста:** контейнеры поднимаются сами (`restart: always`), таймер сверяет состояние и чинит расхождения.

**Изменить лимит:** правится одна запись в `state.json`, таймер пересоздаёт контейнер.

**Обновление образа** (добавили пакет всем): пересборка, затем таймер пересоздаёт все контейнеры с сохранением каталогов.

## 10. Трейдоффы

| Решение | Зачем | Чем платим |
|---|---|---|
| Контейнер на пользователя | отказ одного не трогает остальных | 11 контейнеров, ~340 МиБ в простое, 11 записей в админке |
| Нет общего тома с пакетами | нет общей точки отказа и дрейфа версий | то, что нужно всем, требует пересборки образа; один и тот же пакет разные пользователи качают каждый себе |
| 1.5 ГБ + 0.5 свопа | пережить пик четырёх | тяжёлые сборки могут не влезть — поднимаем точечно |
| 1 CPU на контейнер | пользователи редкие, душить заранее глупо | при одновременной компиляции все ждут |
| LRU 2 ГБ с исключениями | диск не бесконечен, но установленное не пропадает | точную квоту посчитать нельзя: пакеты вне лимита |
| Рецепты в промпт терминала | не править модели руками | промпт один на всех, кто в этом терминале |
| Проверка раз в минуту | не нужен вебхук, работает после ребута | до минуты задержка на создание и удаление |

## 11. Что это не решает

- **Физический предел машины.** Четверо по 1.5 ГБ плюс стек — своп на пределе. Контейнеры разводят отказы, но памяти не добавляют.
- **Диск общий.** 2 ГБ на пользователя считает наш скрипт, а не файловая система. Исключённые каталоги (пакеты, ядра) в лимит не входят, значит фактическое место может быть больше; если скрипт упал, никто не мешает залить весь диск. Настоящая квота — только на уровне ФС.
- **Сеть стека.** Из песочницы видно `litellm`, `postgres`, `open-webui` — без учётных данных доступа нет, но это не изоляция. Строже — отдельная сеть, к которой подключён только WebUI.
- **Системные пакеты.** Только пересборкой образа. Внутри контейнера root нет и не будет.
- **Настоящая изоляция** требует отдельной машины, а не контейнера.

## 13. Зафиксированные решения

1. Файлы удалённого пользователя — 3 дня.
2. Лимиты — 1.5 ГБ памяти / 1 CPU, своп 0.5 ГБ.
3. Потолок каталога — 2 ГБ, LRU, пакетные каталоги исключены.
4. Общего ядра нет. Общий слой — образ.
5. Тулчейн Arduino удалён; Arduino каждый ставит себе сам, Игорю — отдельным шагом после раскатки.
6. «Ожидает» — контейнер не создаётся.
7. Старые файлы Игоря не переносим и не архивируем — удалены.
8. Пакеты — пользователь сам, «для всех» — пересборка образа. Очередь заявок не строим.
9. Рецепты для моделей — системный промпт терминала, не системные промпты моделей.
10. Multi-user mode самого Open Terminal отклонён: требует root внутри контейнера.
