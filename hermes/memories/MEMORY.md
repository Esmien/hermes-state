Отключение навыков в Hermes: config-ключ skills.disabled — список имён-навыков (load_name). Правка: hermes config set skills.disabled '["name1","name2"]' (ключ не в DEFAULT_CONFIG, CLI выдаёт ложное предупреждение о неопознанном ключе, но читатели её читают). Платформенный вариант: skills.platform_disabled.<platform>. Нельзя отключить ESSENTIAL_SKILLS = {hermes-agent}. Применяется при сборке агента → нужно /reload-skills, /new или /restart гейтвея.

Хост-рут этого VPS доступен напрямую как `/` — агент работает на корне хоста, НЕ в контейнере с bind-маунтом. `/mnt/host` НЕ существует; хостовые пути использовать как есть (/home/..., /etc/...). AI-стек: /home/ai_service/ai-stack (детали — skill ai-stack).

Автозагрузка Hermes на этом VPS: гейтвей — systemd USER-сервис /root/.config/systemd/user/hermes-gateway.service (enabled + Linger=yes для root, Restart=always). Boot-уведомление в Telegram: /usr/local/bin/hermes-boot-notify.sh + /etc/systemd/system/hermes-boot-notify.service (oneshot, WantedBy=multi-user.target, enabled); ждёт сеть → процесс гейтвея → контейнеры из /etc/hermes-boot-expected-containers.txt, шлёт через `hermes send -t telegram` (работает без запущенного гейтвея). Лог: /var/log/hermes-boot-notify.log.

Разбор падений контейнеров: docker-autorecover.timer (60 с) → /usr/local/bin/docker-incident-detector.py (только детектит + собирает улики в /var/lib/docker-incidents/, сам НЕ трогает контейнеры) → поднимает Hermes-агента через systemd-run (docker-incident-agent.sh, отчёт в Telegram). Allowlist /etc/docker-autorecover.conf, лог /var/log/docker-autorecover.log, сторож детектора docker-detector-liveness.timer. Перед ручными работами с контейнерами — touch /var/lib/docker-autorecover/pause, после проверки снять.
