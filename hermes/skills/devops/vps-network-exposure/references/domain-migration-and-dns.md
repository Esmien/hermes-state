# DNS отказ и переезд на нормальный домен

## Симптом

Сервис «отвалился», но сервер жив: контейнеры без рестартов, nginx без ошибок, порт
открыт снаружи (проверка через check-host). Клиент показывает `n/a` на всех узлах или
«нет интернета», хотя браузер ту же страницу открывает — он взял адрес из кэша.

## Диагностика (2 минуты)

    dig +short @8.8.8.8   host.example   # SERVFAIL
    dig +short @1.1.1.1   host.example   # NOERROR + IP (кэш)
    dig +short @1.1.1.1   $RANDOM.host.example  # без кэша: SERVFAIL = зона сломана

- `SERVFAIL` у Google и рабочий ответ у Cloudflare = кэш, а не работоспособность.
- Проверить делегирование: `dig +trace host.example A | grep NS` — покажет реальные NS
  (они могут отличаться от тех, что думаешь: `dns1/dns2` вместо `ns1/ns2`).
- Каждый NS прогнать 5 раз и посчитать успехи: `for i in 1..5; dig +short @nsN host`.
  Меньше 5/5 — сервер не годится для делегирования.
- Родительская зона может быть жива, а подзона — нет: проверять надо имя внутри
  делегированной подзоны, а не апекс.

## Почему так бывает

Бесплатные DNS-провайдеры (DigitalPlat и подобные) держат авторитетные серверы,
которые теряют большую часть запросов: 2 ответа из 10. Резолверы получают SERVFAIL
и кэшируют отказ. Бесплатный домен — это единственная точка отказа всей инфраструктуры,
и она ломается молча.

## Порядок переезда

1. Домен у обычного регистратора, NS → Cloudflare (в панели регистратора указать
   выданные `*.ns.cloudflare.com`).
2. Записи: **серое облако** (DNS only) для всего, что не обычный HTTP(S): VPN-входы,
   нестандартные протоколы, сервисы со своим TLS.
3. Сертификаты: на каждое имя vhost на :80 с `/.well-known/acme-challenge/`, затем
   `certbot certonly --webroot -w /var/www/html -d host` (проверено, работает и через
   прокси Cloudflare — путь проходит; 530 = у origin нет vhost для этого имени).
4. Новые vhost'ы делать копией старых с заменой имени и пути к сертификату, чтобы
   не потерять лимиты, таймауты и редиректы.
5. Старые имена оставлять живыми в конфиге как совместимость, снимать после переезда
   пользователей.
6. Обязательно оставить в подписках/конфигах клиентов узел **по IP** (address=IP,
   SNI/Host=домен): TLS проверяется по имени, а DNS для подключения не нужен. Это
   спасает при любом отказе DNS.

## Снятие старого домена: сначала конфиги, потом vhosts

Удалять vhost, сертификат и записи можно только после того, как ни один сервис
больше не зовёт старое имя. Мёртвый хост в конфиге не падает с ошибкой — он молча
возвращает `000`, и фича просто перестаёт работать: у музыкального бота
`ENRICH_URL=https://<мёртвый домен>` означал «обогащение треков не работает», а
ничего в логах об этом не кричало. У Open WebUI то же самое с `WEBUI_URL`
(абсолютные ссылки в письмах, OAuth-редиректах и «поделиться чатом»).

```bash
grep -rl 'old\.domain' /home/ai_service /root/deploy /etc/systemd/system 2>/dev/null \
  | grep -vE 'node_modules|\.git/|backup|\.log'
grep -rhoE '^[A-Z_]+=.*old\.domain' /home/ai_service/*/*/.env /root/deploy/*/.env \
  | cut -d= -f1 | sort -u          # только имена ключей, значения в чат не выводить
```

Те же грабли в `deploy.sh`, `.env.example` и `brand.json` (`legacy_hosts`) — иначе
следующая установка воскресит удалённое. Порядок сноса: конфиги сервисов →
`nginx -t` → reload → `certbot delete --cert-name <host>` → правка конфигов VPN и
`.env.example` → проверка, что новый домен живёт на всех сервисах.

Старое имя после сноса не даёт ошибки: запрос с неизвестным SNI попадает в
`default_server` и получает чужой сайт с сертификатом другого имени — браузер
покажет предупреждение о несовпадении. Скажи это владельцу заранее; отдельную
заглушку он может и не захотеть, если DNS уже мёртв.

## Бесплатный Cloudflare не принимает поддомен как зону

Попытка завести `sub.example.com` отдельной зоной на Free упирается в
`provide the root domain, not a subdomain` — делегировать поддомен в Cloudflare
можно только на платном тарифе. Рабочие бесплатные варианты для поддомена:
**Bunny** (`kiki.bunny.net` / `coco.bunny.net`, есть API — записи можно вести
скриптом) и **Hurricane Electric** `dns.he.net` (только веб-интерфейс).
Порядок обратный интуиции: сначала создать зону у нового провайдера, и только
потом менять NS в панели регистратора — их проверка «external nameservers are not
yet authoritative» отваливается именно на этом шаге.

Отдельно проверь, стоит ли вообще спасать: если провайдер бесплатного
суффикса лежит целиком (`dig NS example.qd.je` → SERVFAIL, авторитетные NS не
отвечают), поддомен остаётся чужой инфраструктурой без гарантий. Честный ответ
владельцу — «это отсрочка, а не решение», и переезд на свой домен всё равно
предстоит.

## Оранжевое облако: когда да, когда нет

- Плюсы: скрывает IP сервера, режет сканеров и DDoS, переживает блокировку IP
  провайдером.
- Порты проксируются только: 80, 443, 2053, 2083, 2087, 2096, 8443.
- Настоящий IP клиента приходит в `CF-Connecting-IP` — без `real_ip_header` fail2ban
  видит только адреса Cloudflare.
- Таймаут ожидания ответа origin ~100 с: рвёт долгие LLM-стримы.
- Правила использования Cloudflare запрещают использовать сервис как VPN-прокси;
  блокировка аккаунта уносит все домены зоны сразу. Для VPN — серое облако.
