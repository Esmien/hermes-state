# Официальный клиент по подписке на нашем хосте (headless)

Когда владелец хочет пользоваться подпиской вендора из терминала, а сервис в РФ не работает
(Antigravity `agy`, Codex CLI, Claude Code, Gemini CLI). Задача: клиент живёт на нашем сервере,
egress зарубежный, владелец заходит по SSH.

## Порядок

1. **Сначала законность поверхности, потом техника.** Первосторонний клиент вендора на нашей машине —
   обычное использование плана. Любая схема, где OAuth подписки обслуживает **другую** программу
   (LiteLLM, OpenClaw, CLIProxyAPI, gemini-cli-openai), — это то, за что аккаунт приостанавливают,
   а на втором страйке банят навсегда. Подписку в гейт не пробрасывать.
2. **Egress прибить только этому юзеру**, не трогая ни хост, ни VPN-стек.
3. **Ставить от этого юзера**, не от root: всё живёт в его `$HOME`, обновление и креды тоже.
4. **Вход по SSH** — code-flow: клиент печатает URL и одноразовый код, владелец открывает URL
   на своём устройстве, присылает код, код уходит в stdin запущенного процесса.
5. **Доказать, какой замок закрыт** — страна запроса или страна аккаунта (см. ниже). Только после
   этого обсуждать подписку и деньги.

## Egress одного юзера на второй адрес

```bash
ip route replace default via <gw> dev <if> src <foreign-ip> table 200
ip rule add uidrange <uid>-<uid> lookup 200 priority 1000
runuser -u <user> -- curl -s https://ipinfo.io/ip    # должен быть <foreign-ip>
curl -s https://ipinfo.io/ip                         # остальные — прежний адрес
```

Пережить ребут — oneshot-юнит с `After=network-online.target`, `Type=oneshot`, `RemainAfterExit=yes`,
и в `ExecStart` те же две строки (`ExecStop` — снять правило и `ip route flush table 200`).

- `curl --interface <ip>` в пробе доказывает только пробу: приложению нужна **правило**, флаг
  действует на один вызов.
- Вердикт вендора не равен ipinfo: тот же адрес у Cloudflare `loc=EE`, у Google `this.gbar_` = `ru`.
  Адрес выбирать по маркеру самого вендора, снятому с этого адреса.

## Два замка

| Что видно | Что это | Чем лечится |
|---|---|---|
| `403 … Detected location: RU` (бэкенд), `this.gbar_` = `ru` (фронт) | страна IP | сменой egress |
| «account is not eligible … not available in your location», страны в тексте нет | страна аккаунта | только country-association form вендора или аккаунт, заведённый в поддерживаемой стране |

Второй замок переживает поддерживаемый egress — перебирать адреса после него бессмысленно.
Проверять до покупки плана: free tier проходит тот же гейт, а на платёжный профиль смотрят отдельно.

## Headless-детали (снято на `agy`)

- Установщик: `curl -fsSL https://antigravity.google/cli/install.sh | bash` → `~/.local/bin/agy`.
  Перед запуском глянуть, какие хосты он тянет, и что в нём нет `sudo`/`rm -rf`.
- **Keyring не строить заранее.** Нужен secret-service с *коллекцией*: D-Bus `CreateCollection`
  в headless умирает «Prompt dismissed», а подсунутый plaintext `~/.local/share/keyrings/login.keyring`
  не регистрируется. Клиент сам уходит на файловое хранилище и пишет в лог
  `Using file-based secret storage at ~/.config/<vendor>/...` — этого достаточно, токен переживает рестарт.
- **Дать юзеру настоящий runtime dir:** `loginctl enable-linger <user>` создаёт `/run/user/<uid>` и
  сессионный bus. Без этого D-Bus ругается, что каталог принадлежит uid 0.
- **TUI вести через pty:** `terminal(background=true, pty=true)` + `process_manage` `write`/`poll`/`log`.
  После вставки строки один `\r` может проглотиться — повторить. Онбординг: Enter подтверждает
  выбранное, `\t` ходит по кнопкам (`[Previous] [Done]`). Чекбокс, который не реагирует на пробел,
  оставить как есть и переключить потом в `/config` — не воевать с виджетом.
- **Ждать код, не перезапуская процесс:** PKCE-verifier и `state` живут в памяти запущенного клиента,
  рестарт превращает присланный код в мусор.
- **Вердикт читать в логе клиента**, не в TUI: там только дружелюбная строка. Ищи
  `loadCodeAssist`, `403 ... LOCATION_NOT_ELIGIBLE`, `Detected location`, `Account ineligible`
  (у `agy` — `~/.gemini/antigravity-cli/cli.log`).
- Квоты и доступ к моделям проверяются на сервере вендора: флаг клиента или старая версия это не обходят.
