# Google: подписка в API и единственный законный маршрут

## Четыре захода и почему все мертвы

- **Официального пути нет.** Ответ Google на форуме разработчиков прямой: стороннее приложение не
  может вызывать Gemini API за счёт квоты AI Pro/Ultra. Плюшки подписки для разработчика живут
  только внутри веб-интерфейса AI Studio, а вызовы API — отдельный проект Google Cloud с отдельным
  биллингом. Это и есть SIWC-эквивалент, которого не существует.
- **Gemini CLI OAuth.** CLI и IDE-расширения Code Assist больше не обслуживают free-аккаунты и
  подписчиков AI Pro/Ultra: для них `Login with Google` не работает вовсе, вход остался только у
  организационных лицензий Code Assist Standard/Enterprise с `GOOGLE_CLOUD_PROJECT`. Вытаскивать
  refresh-токен не из чего — закрыто на их стороне, а не у нас.
- **Antigravity OAuth в сторонний софт.** ToS называет это прямо, с примером в тексте (OpenClaw с
  Antigravity OAuth), и санкция — suspension или termination аккаунтов Antigravity и Gemini CLI.
  Баны идут по общему бэкенду, поэтому бьют и по CLI, и по Code Assist, а **второе нарушение —
  permanent ban**. Апелляции в тредах остаются без ответа. Каскад на весь Google-аккаунт Google
  публично не подтверждает, но и не опровергает; считать надо по худшему — там Gmail и Drive.
- **Реверс веб-клиента Gemini** (cookie + `at`-token, `batchexecute`): технически жив и обёрнут
  библиотеками, но нет function calling, structured output и cache_control — в LiteLLM это
  калека, ломающаяся на каждом релизе веба. Плюс живёт на аккаунте с почтой и диском, а трафик
  Google приоритизирует по «account standing»: помеченный аккаунт душат по ёмкости в часы пик.
  Самая плохая комбинация — высокий риск при низкой полезности.

Правило для ответа владельцу: спроси, есть ли у вендора **белый OAuth для сторонних приложений**.
Нет — вопрос закрывается, а не обходится; «кустарный refresh-скрипт» стоит не денег, а аккаунта.

## Что вместо

- Ключ AI Studio: free tier на Flash-модели, платный Flash дешевле подписки на личном объёме;
  OpenRouter — резервной ногой (credential уже заведён в LiteLLM).
- Если нужны модели Ultra-класса (сторонние модели и «highest» квота приходят только с Ultra),
  законный маршрут один: **их официальный CLI крутится на нашем хосте, владелец ходит в него по
  SSH**. Не «подписка в наш шлюз», а наш хост в их клиенте.

## Antigravity CLI (`agy`) на VPS — механика

- **Вход по SSH решён вендором.** На удалённой сессии CLI печатает URL авторизации плюс одноразовый
  код: открываешь ссылку на своей машине, вставляешь код, handshake завершён. Браузер на сервере не
  нужен.
- **Креды только в системном keyring.** На Linux это secret-service через D-Bus; файлового или
  ENV-fallback для токена нет. На headless нужен живой D-Bus (`export $(dbus-launch)`) и
  разблокированный gnome-keyring/KWallet под тем же пользователем. Симптом отсутствия — зависание,
  D-Bus-предупреждения или `Error: failed to retrieve token: secret keyring is locked`. Это первая
  техническая заноза, и проверять её надо до оплаты подписки.
- **`agy -p` (headless) работает на закэшированных кредах:** без входа падает `authentication
  required`, а не висит. Требующие подтверждения тулы soft-denied (exit 0 + строка в stderr),
  таймаут только через `--print-timeout`, неизвестная модель — non-zero без тихого фолбэка. Разрешения
  живут в `~/.gemini/antigravity-cli/settings.json` (`permissions.allow`, правила `action(target)`).
- **Гео.** Есть список поддерживаемых стран, РФ в нём нет, и требование «аккаунт должен быть
  привязан к поддерживаемой стране». Живая проверка идёт по IP и отдаёт `400 User location is not
  supported` — её ловят даже пользователи с бытовым VPN, то есть это не бан аккаунта. Не выводить
  страну из «сервер в ЕС»: мерить, как Google читает конкретный адрес (`this.gbar_` / ipinfo).
  Если адрес не проходит — привязать egress к нужному адресу policy routing'ом по uid
  (`ip rule add uidrange <uid>-<uid> table <n>` + таблица с `src <ip>`), а не правкой VPN-стека.
- **Квота.** Pro — квота каждые пять часов до недельного потолка; Ultra — highest плюс сторонние
  модели; free — недельная квота. Терминальный агент с длинными сессиями жжёт её заметно быстрее
  веб-чата, поэтому «в терминале» и «дёшево» — не про один и тот же план.
- **Граница, которую нельзя переступать.** `agy` руками в терминале — штатное использование
  первого клиента. Тот же OAuth, подсунутый прокси вроде CLIProxyAPI или `gemini-cli-openai`, чтобы
  торчать из него в LiteLLM/OpenClaw — ровно тот паттерн, по которому вендор банит пачками.
  Прежде чем предлагать «мост», проверить, чей это OAuth.
- **Порядок проверки до денег:** отдельный пользователь → установка CLI → вход на free tier →
  (если отбило по локации) привязка egress → и только потом подписка. Проба на free стоит ноль и
  отвечает на единственный вопрос, который нельзя решить рассуждением.
