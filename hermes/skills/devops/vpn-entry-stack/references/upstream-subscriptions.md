# Upstream subscriptions (relaying nodes)

Two pools, never mixed:

- **relay pool** — every usable upstream node becomes an inbound `/p<i>` (10100+i) on our host plus an outbound `p<i>`; clients reach it through us.
- **whitelist pool** — only the nodes the provider itself labels **«Глушилки»** are exported as raw upstream links (`whitelist_links.json`, 0600) into a **separate subscription of their own**, because under address allowlists our foreign entry is the first thing that gets cut. Classify by the provider's own label, never by geography: `Москва / СПб / Новосиб` nodes are ordinary RU-exit relays and belong in the relay pool, and a plan may contain no «Глушилки» at all (the PC plan has none, the mobile one has ten) — merge the pools only after the owner confirms which nodes he means.

Pitfall: Xray evaluates routing top-down. Inbound rules appended at the end land **after** the catch-all `network: tcp,udp → <default>` and are silently ignored — every relayed path then exits through the default outbound. Keep inbound-tag rules right after the block rules, before domain/ip/catch-all rules, and re-check one or two relayed paths against `ipinfo` after every import.

The provider requires the server's originally registered device identity: `v2rayTun/4.7.0` plus `x-hwid` from `/root/.secrets/vpn-provider-hwid`. The one-user server subscription must reuse that exact identity, not create another device. `python3 /root/vpn-router/fetch_provider_subscriptions.py` fetches both subscriptions into scratch, checks for dummy entries and leaves production untouched. Active copies live under `/root/vpn-router/provider-subscriptions/` (0600, secrets, never commit); `python3 /root/vpn-router/probe_fresh_subscription.py` probes every node of the saved server list including Hysteria2. Compare refreshed exits by content, not index: provider can reorder nodes. On 18.11 the FR credentials changed; updating FR was verified by real WS and body marker. HTTP 200 and a region marker are not proof that an authenticated prompt works.

Do not run the legacy `import_sub.py` on production as a generic refresh: it recreates deleted inbounds and its whitelist regex classifies Russian relays as whitelist. First fetch to an isolated 0600 scratch file, validate actual node names and protocols, compare with active exits, and probe before changing routing. A provider may return fake VLESS entries titled «Данное приложение не обновлено» and «или не поддерживется» without the HWID; never install that response over a working configuration. `probe_sub.py` has stale container assumptions and may write credentials in its work directory. Hysteria2 nodes are unusable by Xray.
