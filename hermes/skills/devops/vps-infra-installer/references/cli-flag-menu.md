# TUI-чек-лист флагов (`FlagMenu`)

Детали к разделу «Выбор флагов» в `SKILL.md`: поведение меню, почему реализация именно
такая и как его тестировать, не рискуя живым хостом.

Запуск без аргументов даёт не анкету вопросов, а чек-лист флагов — владелец не обязан помнить
имена ключей. Поведение: ↑/↓/j/k — курсор, пробел — галочка, Enter — экран подтверждения с
готовой командой, затем `Y` — сохранить выбор в `/etc/vps-infra/install-flags.json` и
выполнить, `n`/Enter — вернуться к списку (дефолт `n`, случайный ввод ничего не запускает),
`q` — выход с кодом 130. Строка списка — ровно в формате «Описание (--флаг)»; владелец
просил именно его, длинные пояснения в той же строке не лепить.

Реализация — сырой `termios` + ANSI-перерисовка на `/dev/tty`, без curses: stdout может быть
трубой (‑‑dry-run в тестах, пайпы), а tty открывается отдельными хендлами на чтение/запись.
Меню вызывается только при пустом `argv`: `bootstrap.sh` и вызовы с флагами идут мимо него.
Пары взаимоисключающих флагов (`--skip-restore`/`--restore`, `--yes`/`--reconfigure`) гасят
друг друга при включении. `VPS_MENU_PRINT=1` — режим самопроверки: печатает выбранный argv и
выходит, не запуская установку; только с ним TUI и можно тестировать безопасно.

**TUI проверять только pty-драйвером, а не `script`+pipe.** `printf ' \ry' | script -qec …`
висит: клавиши уходят в канонический режим до старта программы, а вывод размазан по
ANSI-перерисовкам. Рабочий способ — `pty.fork()`, `os.write` по одной клавише с паузой ~250 мс,
чтение с `select`, жёсткий таймаут и `kill` на выходе (скрипт-образец: `menu_drive.py` в
scratch; на живой прогон — `MENU_DRIVE_LIVE=1`, иначе он ставит `VPS_MENU_PRINT`).
Гонка на стрелках: ESC и `[B` приезжают раздельно, поэтому после ESC нужен `select` с таймаутом
~50 мс и дочитывание второго байта — без этого «вниз» иногда читается как «esc» и тест
показывает не тот флаг.
